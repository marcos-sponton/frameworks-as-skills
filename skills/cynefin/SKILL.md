# Cynefin

Dave Snowden's sense-making framework for deciding what kind of problem you actually have — before you reach for a method. Distilled from the 2003 *IBM Systems Journal* paper (Kurtz & Snowden), the 2007 HBR *A Leader's Framework for Decision Making* (Snowden & Boone), and 20+ years of subsequent refinements — the 2014 renamings (Simple → Obvious → Clear), the 2017 introduction of liminal zones, the 2019–2020 Aporetic Turn, Estuarine Mapping (formalized 2023–2024), and near-daily posts on [thecynefin.co/author/dave-snowden](https://thecynefin.co/author/dave-snowden/) and the [cynefin.io wiki](https://cynefin.io).

This skill helps you sense-make into Cynefin, not sort projects into it. Cynefin is not a 2×2. It is not a categorization tool. It is a framework for contextualizing a situation so you don't apply Complicated methods to Complex problems, or extract "best practice" from a success that only worked because of context you didn't see.

## When this skill activates

**Use this skill when the user is:**
- Deciding what approach to take on a messy, ambiguous, or novel situation.
- Running a post-mortem on a strategy, launch, roadmap, or pilot that didn't behave as expected.
- Defaulting to "best practice" for a problem that isn't routine.
- Reaching for SAFe / Scaled Agile / Design Thinking / Systems Thinking / Lean Startup without asking whether the domain fits.
- Trying to extract a repeatable playbook from a one-off success.
- Designing a pilot — especially if they're planning "the pilot" (singular).
- Facing genuine "we don't know what we don't know" territory.
- Managing crisis / turnaround / high-uncertainty operations.
- Deciding when experts help vs. when experiments help.

**Do NOT use this skill when:**
- The user has a genuinely routine operational task in the Clear domain (invoice processing, hand-luggage rules). Cynefin's answer there is "use best practice" — the framework is overkill.
- The user asks for a diagrammatic summary of Cynefin. Give them the [cynefin.io wiki](https://cynefin.io/wiki/Cynefin_Domains) and the [Snowden & Boone HBR paper](https://hbr.org/2007/11/a-leaders-framework-for-decision-making) and don't run the framework.
- The user wants Cynefin as a project-sorting tool. Push back: it isn't one. Offer sense-making instead.
- The user is looking for a competitive-choice framework — that's Playing to Win or Rumelt's kernel, not Cynefin.

If the situation is ambiguous, sense-make first — start from Confusion, not from categorization.

## The five domains at a glance

Cynefin distinguishes five domains by the **type of constraint** operating and by the **relationship between cause and effect**:

| Domain | Constraint | Cause-effect | Decision model | Practice |
|---|---|---|---|---|
| **Clear** (ex-Obvious, ex-Simple) | Rigid / fixed | Self-evident | Sense → Categorize → Respond | **Best practice** — the only legitimate place for it |
| **Complicated** | Governing | Discoverable via analysis | Sense → Analyze → Respond | Good practice — experts |
| **Complex** | Enabling | Coherent only in hindsight | **Probe → Sense → Respond** | Emergent / exaptive — parallel safe-to-fail probes |
| **Chaotic** | Absent | None | Act → Sense → Respond | Novel practice — impose constraint first |
| **Confusion** (central) | Unknown | Unknown | — | Aporetic if aware; dangerous if not |

The border between Clear and Chaotic is a **cliff** — a catastrophic fold. Rigid constraints do not degrade gracefully; they collapse. See `references/method.md` for detail on constraints, liminality, and the aporetic turn.

## How to use this skill in a session

1. **Start in Confusion.** Do not categorize first. Assume you don't know which domain until the situation has been contextualized. Premature categorization is Snowden's most-named error. Load `references/method.md` for the five domains and their constraints.

2. **Identify the constraint that's actually operating,** not the constraint you wish were operating. Rigid → Clear/Complicated. Enabling → Complex. Absent → Chaotic. If you can't tell, that's aporia — legitimate. Load `references/heuristics.md`.

3. **When the user reaches for a Complicated method on a Complex problem — push back specifically.** Root-cause analysis, expert consultation, single-pilot roadmaps, best-practice extraction from a Complex success — all wrong tool. Name it. Don't blur. Snowden doesn't. Load `references/voice-and-tone.md`.

4. **When the user invokes SAFe / Design Thinking / Systems Thinking / Learning Organization for a Complex problem — push back in Snowden's register.** Not diplomatic. Attack the framing before offering the alternative. Frame Cynefin as the diagnostic that helps you apply those frameworks *where they actually work*, not as a rival methodology. Load `references/voice-and-tone.md` and `references/applications.md`.

5. **In the Complex domain, prescribe multiple parallel safe-to-fail probes** — not a single pilot, not fail-safe design, not root-cause analysis. Load `references/heuristics.md` for the Complex-domain playbook.

6. **When the topic goes beyond the 2007 HBR — pull post-book material.** SenseMaker, the Aporetic Turn, Estuarine Mapping, EU Field Guide, the SAFe / Design Thinking attack essays, anticipatory triggers. Load `references/post-book.md`.

7. **Cite sources.** When you introduce a specific device or quote, name the source: HBR 2007, cynefin.io wiki page, a specific thecynefin.co essay, Jim Rutt Show EP184, YouTube talk. Snowden publishes daily; the reader can go deeper.

## Non-negotiables

- **Sense-making, not categorization.** Cynefin is a framework you contextualize *into*, not sort projects *into*. If the user is using it as a 2×2, correct the misuse. This is Snowden's most-repeated correction.
- **Constraints are the tell.** The type of constraint operating tells you the domain, not the topic. A "software project" can be Clear, Complicated, Complex, or Chaotic depending on the constraint.
- **Best practice is a Clear-domain move only.** Applied elsewhere it's brittle. When the user invokes best practice for a non-Clear situation, name the misapplication.
- **Multiple parallel probes in Complex, not one big pilot.** Single-pilot syndrome is a Complicated-methods-in-Complex-domain error.
- **Fidelity to Snowden's voice.** Sharp, specific, willing to attack. Not diplomatic where diplomacy hides the diagnosis. See `references/voice-and-tone.md`.
- **Positioning.** Cynefin is a diagnostic that helps you apply Agile / Design Thinking / Systems Thinking *correctly* by first identifying the domain. The voice attacks the misapplication (usually SAFe, Design Thinking as commodity template, Systems Thinking as engineering-mechanical), not the underlying practice done in-context.
