# Thinking in Systems — Prompt templates

> Copy-paste templates users can adapt. Each starts with a user situation and invokes the skill in a shape the assistant can execute well.

## Diagnose a recurring problem

```
We keep having this problem: {{describe the pattern that keeps recurring}}.
We've intervened with {{list past interventions}}. The problem keeps coming back.

Please apply Meadows's method:
1. Ask me for the behavior over time (draw the graph — growth? oscillation? overshoot? drift?).
2. Identify the stocks, flows, and feedback loops in play.
3. Match the pattern to a system archetype if one applies (fixes that fail, shifting the burden, drift to low performance, tragedy of the commons, seeking the wrong goal, escalation, success to the successful, rule beating, limits to growth).
4. Place our past interventions on the 12 Leverage Points ladder. Are we all playing at points 10–12 while ignoring 3–5?
5. Prescribe a next intervention with Dancing-with-Systems humility (small step, monitorable, revisable). Name what to watch to know whether it's working.

Cite Meadows sources (Thinking in Systems chapter, Leverage Points essay, Dancing with Systems).
```

## Place an intervention on the leverage-points ladder

```
Here's an intervention we're considering: {{describe intervention}}.

Please place it on Meadows's 12 Leverage Points ladder (from lowest leverage — constants/parameters/numbers — to highest — transcending paradigms). Then answer:

1. What leverage point is this intervention operating at?
2. What higher-leverage interventions are being ignored?
3. If we're stuck at a low leverage point because the higher ones are "unrealistic," name what those higher-leverage interventions would look like, even if we can't pursue them immediately.
4. What structural / feedback-loop change would make this intervention actually stick (rather than the pattern returning)?

Cite the 1999 Leverage Points essay and Thinking in Systems.
```

## Archetype recognition workflow

```
Here's the situation: {{describe}}. Here's what's been happening over time: {{describe the trajectory}}.

Please run Meadows's archetype-recognition workflow:
1. Which of the canonical archetypes does this look like? (Fixes that fail / policy resistance; tragedy of the commons; drift to low performance; escalation; success to the successful; shifting the burden; rule beating; seeking the wrong goal; limits to growth.)
2. What's the structural pattern that produces this archetype (stocks, flows, feedback loops, delays)?
3. What's the archetype's characteristic escape route?
4. What's the intervention people are most likely to reach for that will make it WORSE?
5. If no archetype fits cleanly, describe the structure directly rather than force-fitting.

Cite Thinking in Systems Chapter 5 (System Traps and Opportunities).
```

## Post-mortem via Meadows

```
{{Program / policy / launch}} didn't behave the way we expected. Standard post-mortem is producing "root cause" answers that feel too neat. Help me do a Meadows post-mortem instead.

What happened: {{describe}}.
What we expected: {{describe}}.
The "root cause" we've been converging on: {{describe}}.

Please:
1. Recognize that Complex systems have entangled contributing structures, not a single root cause — root-cause thinking is a Complicated-domain move applied to a Complex problem.
2. Trace the stocks, flows, and feedback loops. Where were the delays? What balancing loops resisted the intervention? What reinforcing loops were unaccounted for?
3. Match to an archetype if one applies. Did we fall into fixes that fail, shifting the burden, seeking the wrong goal, or another?
4. Diagnose which leverage point our intervention was at. Would a higher-leverage intervention have worked?
5. What did we intervene in without observing behavior over time first?
6. What did we prescribe without the Dancing-with-Systems humility — no monitoring, no willingness to change course?

Cite Meadows sources.
```

## Push back on symptom-attacking

```
Here's the intervention people are converging on: {{describe}}.

I suspect it's attacking a symptom, not the structure. Please apply Meadows's structural-vs-symptomatic analysis:
1. What is the symptom the intervention addresses?
2. What structure (stocks, flows, feedback loops) produces the symptom?
3. Where does the proposed intervention sit — at the symptom (usually leverage points 11–12) or at the structure (points 3–8)?
4. If the intervention is at the symptom, name the specific fixes that fail dynamic likely to play out — how will the symptom return? Or which shifting the burden pattern is being installed?
5. What structural intervention (higher on the leverage ladder) would actually address the recurrence?

Be direct — Meadows's discipline is to name the misapplication specifically, without hostility toward the people making it (bounded rationality). Cite sources.
```

## Apply the Dancing with Systems humility check

```
Here's the intervention we're planning: {{describe}}. Timeline: {{describe}}. Success metrics: {{describe}}.

Please apply the Dancing with Systems humility check:
1. Are we prescribing an intervention or attempting to control the system?
2. Are we planning small steps or a big-bang change?
3. What are we going to monitor to know whether the intervention is working?
4. Under what conditions would we change course?
5. What surprises should we prepare for?
6. Are we accounting for delays — will we judge the intervention too early?
7. Whose well-being counts in this intervention? Have we expanded the boundary of caring wide enough?
8. Is the goal of the intervention aligned with the goal we actually care about, or with a proxy?

Cite Dancing with Systems (donellameadows.org/archives/dancing-with-systems/).
```

## Distinguish system archetypes

```
I'm trying to figure out which archetype this is: {{describe pattern}}.

Please diagnose:
1. Draw the graph — what's the behavior over time?
2. Which archetypes could this be? (Enumerate 2–3 candidates.)
3. What structural difference distinguishes them?
4. What questions would I ask / what evidence would I look for to distinguish?
5. Provisional diagnosis — but honest about which parts I need more observation to confirm.

Meadows insists on behavior over time before naming; if we don't have the trajectory, say what we need to observe.
```

## Design a high-leverage intervention (paradigm / goals level)

```
The obvious interventions at leverage points 10–12 (adjust parameters, buffers, physical structure) aren't shifting {{outcome}}. I want to think about higher-leverage interventions.

Please:
1. Diagnose the current paradigm (point 2) operating on this problem. What are the unstated assumptions that make the current system feel inevitable?
2. Diagnose the current goals (point 3) as revealed by system behavior — not the stated goals.
3. What paradigm-level shift would change the goals, and what would that imply downstream (rules, information flows, structure)?
4. Are there specific interventions at points 3–5 (goals, self-organization, rules) that we've been dismissing as "unrealistic"? Name them.
5. Apply Dancing-with-Systems humility to any prescription — paradigm shifts aren't on-demand; small steps that make the paradigm visible may be the only accessible move.

Cite Meadows on the leverage points ranking and her critique of the growth paradigm (Limits to Growth).
```

## Cross-check with Cynefin

```
I'm working on {{situation}}. I've been using Meadows's method — stocks, flows, archetypes, leverage points. I want to cross-check: am I in a Complex domain where Meadows's structural analysis applies, or somewhere else?

Please:
1. Sense-make the Cynefin domain (Clear / Complicated / Complex / Chaotic / Confusion).
2. If Clear or Complicated: Meadows may be overkill; recommend a simpler tool.
3. If Complex: apply Meadows's structural analysis with Cynefin's Complex-domain posture (multiple parallel safe-to-fail probes, amplify / dampen). Note that structural analysis in a Complex domain requires the Dancing-with-Systems humility.
4. If Chaotic: defer Meadows; use Cynefin's act → sense → respond first.
5. If aporetic (genuinely don't know): legitimize the not-knowing per Cynefin; run parallel structural hypotheses per Meadows.

Cross-link [[cynefin]].
```

## Compare Meadows vs. an adjacent framework

```
I'm deciding whether to use Meadows (Thinking in Systems) or {{Cynefin / Theory of Constraints / Fifth Discipline / Playing to Win / Rumelt's kernel}} for {{situation}}.

Help me pick. If the answer is "use both, in this sequence," tell me the sequence. If Meadows sits upstream / downstream / at a different level, say so. If the answer is "use something else entirely," tell me that too.

Consider:
- Meadows is strongest for diagnosing recurring patterns, placing interventions on the leverage ladder, and paradigm-level analysis.
- Cynefin is strongest for sense-making which decision-making domain you're in.
- Theory of Constraints is strongest for operational bottlenecks.
- Fifth Discipline is strongest for organizational-learning practice inside a firm.
- Playing to Win / Rumelt are strongest for competitive strategy choices.
```
